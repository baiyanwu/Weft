# weft

一台 Mac 与多台 Android 设备共享鼠标。各设备可以同时保持连接，同一时刻只控制一台；通过屏幕边缘、菜单栏或快捷键切换。

当前版本 **0.2.0**。macOS Bundle Identifier 与 Android 控制程序的 Java 包名均为 `io.baiyanwu.weft`。

## 运行

打开构建生成的 `weft.app`。设置窗口和菜单栏使用同一份设备状态；关闭设置窗口后，应用继续在菜单栏运行。

左键或右键点击菜单栏图标均打开同一个面板，再次点击可收起。菜单栏面板在点击外部区域或切换到其他应用时自动收起；面板内的操作仍正常响应。

首次运行需在 **系统设置 → 隐私与安全性 → 辅助功能** 中允许 weft。若没有列出应用，用 `+` 添加当前构建的 `weft.app`。授权后自动启用鼠标监听。

Android 需开启 USB 调试，并允许这台 Mac。无需安装 APK 或 root。ADB 从以下位置查找，也可通过 `WEFT_ADB` 环境变量指定：

- `~/Library/Android/sdk/platform-tools/adb`
- `/opt/homebrew/bin/adb`
- `/usr/local/bin/adb`

第一次运行多设备版本时，会导入当前已授权的设备，并迁移旧版的设备位置、速度和出入口屏幕设置。以后通过“添加设备”添加新设备。

## 布局与独立设置

侧栏选择设备后，可单独设置 Mac 出入口屏幕、上/下/左/右位置、鼠标速度（0.7× / 1× / 1.4×）、自动连接和自动跨屏。设置自动保存，选中设备不会立即切换鼠标控制。

Mac 与所有 Android 设备按系统报告的屏幕尺寸，以同一倍率缩小绘制，并显示当前横竖屏。手机和平板使用同一套布局、输入设备准备和跨屏逻辑，都显示在同一画布中。拖动设备可贴到 Mac 的上、下、左、右任一边，沿边偏移会保存。绿色线段表示两块屏幕实际接壤的区间，只有该区间可以双向自动跨屏。拖动时画布比例固定，支持边端和中线对齐，并避免设备矩形相互覆盖。

设备名称、尺寸和状态按矩形的实际可用空间展示：能完整容纳时放在屏幕内，空间不足时移到外侧信息卡，用细线指向对应屏幕。外侧信息卡会避让屏幕和其他信息卡，也支持选中和拖动设备；屏幕本身的尺寸比例和绿色接壤区间保持不变。手机和平板共用这套规则。

上下跨屏保留接缝处的横向位置，左右跨屏保留纵向位置。两端的坐标先换算到共同的尺寸尺度，再减去屏幕偏移；不把 Mac 的入口区间拉伸到设备整条边，也不追加入口的沿边缩进。设备类型仅用于图标和名称展示，不参与布局和控制路径选择。

屏幕尺寸和朝向在连接后读取，离线时保留最后的尺寸与贴边偏移。没有历史尺寸的设备显示连接提示；系统未提供有效物理 DPI 时使用估算大小并标注。实际摆放的对齐精度受设备报告的尺寸精度影响。

“重置布局”将设备放到主显示器下方，按尺寸自动避让，出入口恢复到主显示器。若所选 Mac 显示器暂时不可用，会临时使用主显示器，并保留原来的屏幕选择。

当前跨屏关系为 **Mac ↔ 每台 Android**。Android 设备之间经 Mac 切换；不支持直接从一台 Android 的边缘进入另一台 Android。真实 Mac 显示器之间的移动优先。

## 控制与连接

| 操作 | 方法 |
| --- | --- |
| 自动进入 Android | 到对应 Mac 的绿色接壤区间，向外移动即触发 |
| 自动返回 Mac | 到设备靠近 Mac 的接壤区间，继续向外推 |
| Mac / 上次设备切换 | `Control + Option + M`；上次设备不可用时选择可用设备 |
| 立即返回 Mac | 左侧 `Option` 或 `Esc` |
| 指定控制设备 | 菜单栏面板 → 对应设备“进入” |
| 打开菜单栏面板 | 左键或右键点击菜单栏图标；weft 窗口内也可用 `Command + Shift + M` |
| 打开设置 | 菜单栏“设置…”；weft 内 `Command + ,` |
| 断开一台设备 | 设备详情“断开”；本次运行中不会被自动连接立即接回 |
| 恢复单台连接 | 设备详情“连接”；无需重新添加设备 |
| 永久删除设备 | 左侧设备行的垃圾桶按钮；删除设备及其保存的设置，再次使用需手动添加 |
| 全部连接 / 断开连接 | 设置窗口“我的设备”右侧；有设备已连接时显示“断开连接”，否则显示“全部连接” |
| 暂停 / 恢复全部 | 菜单栏面板；保留设备配置 |

“自动跨屏”针对每台设备独立保存。关闭某台设备的开关，只停止从 Mac 边缘自动进入该设备，其他设备不受影响；菜单和快捷键仍可进入该设备，Android 边缘返回及紧急退出仍可用。通用设置中提供前往设备设置的入口，不再有自动跨屏总开关。

从旧版首次升级时，已有设备的自动跨屏默认开启，不再沿用旧全局开关的关闭状态，之后按每台设备分别保存。关闭某台设备的“自动连接”不会立即断开现有连接，但会停止后续自动重连。全局暂停和手动断开属于本次运行状态；重新启动时按各设备保存的自动连接设置连接。

每轮连接对每台设备最多尝试 **3 次（含首次）**。连续失败达到上限后停止，状态显示“已停止重连”，设备详情保留停止提示和具体原因；设备扫描、重新插拔或通道切换不会清零次数。再次点击“连接设备”或“全部连接”会开始新一轮最多 3 次尝试。连接成功后次数清零，后续断线可按自动连接设置开启新一轮。

“自动连接”控制是否自动发起连接轮次；关闭时，用户仍可主动点击连接，授权一轮最多 3 次的尝试。关闭开关会清除待连接请求并取消后续重试和正在进行的自动尝试；已成功连接的设备继续使用，已经开始的手动尝试允许完成。达到上限后需主动点击连接，开关变化本身不会解除停止状态。

仅共享鼠标移动、五个鼠标按键和滚轮，不共享键盘、音视频或剪贴板。左右键保留 Android 原生鼠标语义。按住鼠标拖拽时不自动跨屏。

“全部连接”会尝试连接所有已添加设备，包括关闭自动连接或之前手动断开的设备；若全局连接已暂停，也会恢复连接尝试。只要有一台连接成功，按钮就变为“断开连接”；没有设备连接成功时保持“全部连接”。各设备保存的自动连接设置不会因此改写。

左侧每台设备始终显示删除按钮，在线、离线和暂停时均可删除。点击后立即结束该设备的控制会话，并从设备列表、布局、菜单栏和保存的配置中移除；删除最后一台设备后，重新扫描或重启也不会自动加回。设备仍可在“添加设备”中被发现，手动重新添加时使用默认设置。

## 添加 USB / Wi-Fi 设备

USB：接入设备、允许调试，在“添加设备 → USB 连接”的已发现列表中选中设备，再点击“添加并连接”。授权未完成的设备会提示处理授权；已经添加的设备会单独标注。

Wi-Fi 分为两步：先在“连接到 Mac”中填写无线调试主页面上的连接地址，再填写下方配对码页面上的配对地址和六位配对码，点击“配对并连接”；两个地址的端口通常不同。IP 使用四段数字输入，每段范围 0–255；端口单独输入，范围 1–65535。配对码为六格明文数字，支持连续输入和整段粘贴；也可以在地址任一输入格粘贴完整的 IPv4 地址或 `IPv4:端口`。信息完整有效后才可发起连接。已经与 Mac 配对的设备可以勾选“此设备已与 Mac 配对”，只填写连接地址。连接成功后，在第二步列表中选中设备并点击“添加设备”。

已识别硬件序列号的同一设备通过 USB 和 Wi-Fi 同时出现时合并为一个配置；新建连接优先使用 USB，正在使用的可用通道会继续保留。无线调试的配对和连接入口已实现，本次实机验收使用 USB，未验证 Wi-Fi 延迟和网络变化后的表现。

## 尚未开放的 UI 入口

新设计中的“登录时启动”和“识别屏幕”仅展示 UI，标为“暂未开放”，不执行操作或保存新设置。添加设备页中的未开放名称 / 位置预设已删除。现有的单设备自动连接、屏幕选择、连接 / 断开、日志查看与诊断导出继续使用原有实现。

设备详情中的更多菜单已移除，包含重命名、手动切换设备类型、移除设备，以及重新连接、设备详情、单台设置重置的预留入口。

诊断页展示已知的权限、连接工具和设备连接状态；“刷新设备”只调用现有设备扫描，不表示执行完整健康检查。

## 切换与恢复机制

- 每台 Android 设备只预热一个常驻绝对鼠标，同一份报告发送完整 X/Y、五键和双向滚轮。正常往返不在两套输入设备间交接，不注册或移除设备。
- Mac 维护连续逻辑坐标，按两屏物理尺寸换算位移并应用速度倍率。后续移动不再使用 Android 相对鼠标加速；速度手感需人工验收。
- 跨屏不激活 weft 或设置窗口。Mac 光标在隐藏状态下停靠入口，返回时先定位再显示；后台隐藏接口不可用时保留 Mac 控制。
- 进入与后续移动按同一通道顺序发送，收到确认前继续处理移动和按键，不丢弃或集中回放位移。相邻纯移动可合并到最新位置，按键、滚轮、进入和释放保持顺序。
- 双向接续越过接缝后的剩余位移；返回由连续逻辑轨迹穿越实际接壤区间判断，不使用陈旧边缘反馈。没有推边等待、累计推力、切换冷却或进入后禁返时间窗；拖拽期间不自动跨屏。
- 连接准备校验实际注册、设备能力、位置和方向。进入不执行三次串行查询；后台异步确认本次已提交轨迹的位置后恢复图标，输入不等待查询。当前 shell 没有 MONITOR_INPUT 权限，保留诊断接口用于显隐确认和显式 probe；窗口未接受图标时异步重试。
- 返回释放按键并隐藏光标，设备保持注册；窗口变化时重新应用隐藏。继续使用 Android 16 窗口监听和输入服务，只保存默认屏幕的输入令牌。
- 协议版本为 3。进入、输入和释放携带会话序号，输入携带递增序号；拒绝旧会话、重复或倒序输入，忽略迟到回复。旧包与新版控制程序不混用。
- 尺寸和旋转由准备及心跳校验，变化后退出旧会话并重新准备。发送逻辑坐标不额外旋转；诊断反馈统一换回逻辑坐标。
- 每台设备独立连接和心跳。断线、进入失败或无法可靠显示时返回 Mac；保留每轮最多 3 次的连接规则。暂停、退出、心跳停止或通道关闭时清理设备。

## 构建与测试

使用 Xcode 打开 `Weft.xcodeproj`，选择 Weft scheme 和 My Mac。`Command + B` 构建，`Command + R` 运行，`Product → Archive` 归档。需要 JDK 17+ 和 Android SDK 36 / Build Tools 36.0.0；Android 控制程序由 Xcode 自动编译并嵌入应用。

命令行构建：

```sh
xcodebuild -project Weft.xcodeproj -scheme Weft -configuration Debug \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath outputs/DerivedData build
```

上例适用于 Apple Silicon，Intel Mac 使用 `arch=x86_64`。应用位于 `outputs/DerivedData/Build/Products/Debug/weft.app`。中间文件由 Xcode 的 DerivedData 管理；`ANDROID_SDK_ROOT` 可以覆盖 SDK 位置。

需要时在 Xcode 中用 `Command + U` 运行测试。普通构建不执行测试，也不自动连接实体设备。正式签名、公证见 [发布流程](RELEASING.md)。

双设备操作脚本只在主动选择实机验证时使用，先退出正在运行的 weft：

```sh
python3 scripts/test_devices.py --serial DEVICE_SERIAL_1 --serial DEVICE_SERIAL_2
```

设备序列号按实际情况替换。脚本只移动鼠标，不执行 Android 点击或键盘输入；结果写入 `outputs/device-multi-results.json`。脚本默认使用上述 Debug 构建内的控制程序，也可用 `--dex` 指定其他构建的 dex。

## 适用范围

当前实测 OnePlus OPD2413 和 Seeker，两台均为 Android 16 / API 36。Android 端以已授权 ADB shell 身份使用 `/dev/uhid`，坐标反馈来自系统输入服务的内部诊断格式；其他系统版本、厂商、游戏独占鼠标及特殊页面需另行验证。主机不开放额外服务端口，不记录应用名称或屏幕内容。

项目独立实现轻量控制程序，没有打包或修改 scrcpy。公开验证范围见 [验证说明](VERIFICATION.md)，私人开发记录不包含在仓库中。
